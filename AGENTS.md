# AGENTS.md

Lead-brain: local-lead finder for freelance web devs. Manual CSV (or OSM discovery) → Playwright fetch → LLM extract → deterministic scoring → SQLite → CSV exports → Streamlit dashboard, plus a local semantic search index and a grounded AI chat over the stored leads. Python 3.11+ (venv currently 3.14), stdlib-only test stack.

**Bug tracker:** `bug.md` at repo root — the full audit backlog (severity, file:line, repro, fix). Check it before touching pipeline/storage/engine code; keep it current when you fix something.

## Commands

- Tests: `.venv/bin/python -m unittest discover -s tests` (stdlib `unittest`, no pytest). Single file: `.venv/bin/python -m unittest tests.test_scoring_dimensions`. Known env-dependent failure to ignore: `tests.test_crm_service.CrmDashboardDataPathTest.test_records_from_editor_df` fails when `data/lead_crm.xlsx` exists locally (it reads the real workbook, not the temp DB) — it passes on a fresh checkout.
- No linters, formatters, or type checkers are configured. Verification = full test suite + `.venv/bin/python -m compileall -q main.py dashboard.py src` + a smoke run.
- Offline smoke (no API key, no crawl): `.venv/bin/python main.py --input business_urls.sample.csv --limit 3 --no-crawl --log-file none`
- Init/migrate DB: `.venv/bin/python -m src.storage.init_db`
- Dashboard: `streamlit run dashboard.py`
- Playwright (required for real fetching): `python -m playwright install --with-deps chromium`. Without it, **every** seed (even ones with URLs) is routed through `_process_seed_no_fetch`, which stores `website_url=NULL` under a synthetic `biz://` key — URL is unrecoverable and a later Playwright run creates a duplicate row (bug.md CRIT-1). Never run a real CSV/discovery run without Playwright.
- Search: the engine defaults to a stdlib hash embedder + SQLite store — zero extra deps. `requirements-search.txt` (sentence-transformers, chromadb) is optional; opt in via `.env` `SEARCH_EMBEDDER=sentence` / `SEARCH_VECTOR_STORE=chroma` ("auto" enables them when importable). Indexing runs at the end of every pipeline run — skip with `--no-index`, force a rebuild with `--rebuild-index`.

## Architecture

- Pipeline (`main.py` → `_run_seeds`, then `_export_csv_for_run`, then `_index_run_leads`): per seed — fingerprint (offline) → crawl (contact extraction runs inside on raw HTML) → SEO audit (offline) → visual audit (offline, screenshot-based) → LLM extraction → scoring (offline) → opportunity detection (offline) → `upsert_lead` (contact fields merged) → persist detections/audit/score/opportunities → CSV export → search index. No-website seeds take `_process_seed_no_fetch`, which still scores and derives contact fields from the CSV seed row. `extraction_success` is the LLM's self-reported flag and run stats `ok`/`failed` count upserts, not extractions — a "ok=6 failed=0" run can hide failed extractions (bug.md H-3). Dashboard-triggered discovery (`run_discovery_pipeline`, `main.py:386`) skips the enrichment pre-pass that CLI runs.
- Deterministic engines — `src/fingerprinting/`, `src/seo/`, `src/scoring/`, `src/opportunities/`, `src/visual/`, `src/contact/`: pure functions, **no network, no LLM, no DB access**. The LLM only extracts; engine output reaches the LLM as neutral banner text (`to_llm_text`), never as instructions to infer.
- Contact engine (`src/contact/`): deterministic extraction of owner, address, postal code, opening hours, social URLs, contact page/form URLs, maps link, service areas — **plus** email/phone recovered from JSON-LD, `mailto:`/`tel:` links, Schema.org microdata (`microdata.py`), and visible text (`recovery.py`, conservative token regex + date/year-range guards). Runs inside the crawler on raw HTML **before** boilerplate removal (home + fetched + cached pages) so header/footer/form markup survives; per-page facts merge via `ContactSignals`/`merge_contact_signals`, then the strongest candidate wins lead-wide (`extractor.py::_resolve_best`). The crawler always visits a contact page first (`page_ranker.py::find_contact_links` + `focused_crawler.py`, slot reserved by dropping the weakest ranked page, never exceeding `MAX_CRAWL_PAGES`). Stored as lead columns (`service_areas` as JSON; `phone_source`/`email_source`/`phone_confidence`/`email_confidence`). Social URLs are the only contact facts shown to the LLM (neutral banner via `_crawl_summary`); the rest is deterministic-only.
- Contact precedence (`src/contact/sources.py`): source ranks JSON_LD 100 > MAILTO/TEL 90 > SCHEMA 85 > VISIBLE_TEXT 70 > LLM 60 > OSM 40 > CSV 30. `main.py` merges via `pick_across_sources(deterministic, LLM, seed)` — **deterministic beats LLM** (the old `extracted or seed or contact` order is gone); no-fetch seeds tag phone/email with `csv`. Best-email tiebreak: business-domain > hello/contact > sales/support > info > other, then first-seen; best-phone: leading `+`, then first-seen.
- Visual audit (`src/visual/`): bounded offline audit (Playwright screenshots or reused cached HTML + CV-lite heuristics) after SEO and before extraction; multimodal summary gated behind `VISUAL_LLM_ENABLED`, degrades gracefully without an API key.
- `ScoringInputs` (`src/scoring/base.py`) is the shared input contract: main.py builds it once and feeds `score_site_lead` and `detect_opportunities`. All fields optional — engines must never crash on missing data (enforced by `test_scoring_missing_data.py`). No-website leads must produce empty/no-op engine results, not errors. Known anomaly (not to be "fixed" ad hoc): a no-website/no-contact lead scores 60 "Warm" and outranks real leads because missing dimensions' weight is redistributed and `outreach_potential` rewards missing website (bug.md H-1). `OpportunityReport.contact` carries input-derived contact context (website, phone, email, address, social URLs, primary contact, best contact method) for reporting only — it never affects scores.
- Engine tunables live in `ScoringConfig` / `OpportunityConfig` (`config.py`); no magic numbers in engine code. Detector order/registry: `src/opportunities/registry.py`.
- Almost every pipeline stage is wrapped in try/except — a failure normally doesn't break the run; the two known unwrapped gaps are the crawler call (`main.py:506`) and no-fetch scoring (`main.py:887–900`), where one exception aborts the whole batch (bug.md M-11). LLM extraction degrades to a failed-lead dict without `OPENROUTER_API_KEY`.
- Shared intelligence for search/chat/dashboard: `src/storage/search.py::leads_intelligence` returns per-lead `{lead, detections, seo, visual, score, opportunities}` dicts; the `lead` dict is `SELECT *` (all contact columns included, `service_areas` decoded). Builders consume these dicts, never raw SQL.
- Search (`src/search/`): one deterministic semantic document per lead (`build_lead_document`; labelled sections incl. contact info and `no phone`/`no email` markers; metadata whitelisted via `METADATA_KEYS`). `SearchService` is the facade; canonical storage is the `lead_embeddings` table; ranking lives in `ranking.py` — don't change similarity/ranking as a side effect of editing documents.
- Chat (`src/chat/`): grounded assistant over the same intelligence. `context_builder.build_lead_block` packs one lead into a compact block (cap `MAX_BLOCK_CHARS`); retrieved DB/crawl text is untrusted data (`safety.sanitize_text`, `<lead_data>` fence) and answers are checked by `validate_grounded_answer`. Synthesis backends (`CHAT_LLM_BACKEND`: auto/ollama/openai-compatible/none) use stdlib urllib only.
- Outreach (`src/outreach/context.py`): deterministic digest (`build_outreach_context`) shaped for a future outreach generator — it never writes email copy.
- Website enrichment (`src/enrichment/`): pre-pipeline recovery of websites for website-less seeds (`main.py::_enrich_seeds_pass`, before the crawl; skipped under `--no-crawl`/`--no-enrichment`/`ENRICHMENT_ENABLED=0`). Sources are free and local-first: private email-domains (`email_domain`) and an anonymous DuckDuckGo HTML search (`web_search`, endpoint via `ENRICHMENT_SEARCH_URL`; search is best-effort discovery — on bot-flagged IPs it yields nothing, email-domain candidates still work). Every candidate is deterministically verified with a bounded stdlib fetch (truncated at `ENRICHMENT_MAX_FETCH_BYTES`, never rejected for size); scores: brand title-sequence 0.55 / phone 0.35 / email-domain 0.35 / location 0.15 / category 0.05, accepted ≥ `ENRICHMENT_ACCEPT_THRESHOLD` (0.75). Found sites ship to the existing `biz://`-keyed row via `apply_enrichment_to_existing` (migration to the real URL key), stored on lead + cache (`website_enrichment_cache`); failures are never cached, `not_found` is (TTL `ENRICHMENT_CACHE_TTL_DAYS`). OSM discovery (`src/discovery/osm.py`) already reads `website`/`contact:website`/`contact:web`/`url` tags.
- Engines consume `ScoringInputs`-shaped dicts; per-page SEO signals live in `seo_audit["pages"]` (HTML-only aggregates like `pages_with_title` are only meaningful when `html_pages > 0`; legacy text-only cached pages are excluded, never counted as missing).

## DB conventions (src/storage/)

- Schema: `SCHEMA_SQL` in `src/storage/db.py` (`CREATE TABLE IF NOT EXISTS`) plus additive `ALTER TABLE` migrations in `_apply_migrations` (`_ADDITIVE_LEAD_COLUMNS`). **Adding a column requires both** — existing DBs (`data/leads.sqlite`) only get it via the migration.
- Per-lead rows use delete-then-insert `replace_*` (detections, seo audit, visual audit, `lead_scores`, `business_opportunities`) so re-runs stay consistent.
- After `upsert_lead`, look up `lead_id` via `get_lead_id_by_url(normalize_url_for_dedupe(url))` — upsert dedupes by normalized URL. **Only phone/email are preserved**, not clobbered: `upsert_lead` (`src/storage/leads.py:159–204`) compares incoming vs stored via `better_contact` (validity, source rank, confidence; ties keep existing) — a weaker re-run never overwrites a stronger stored value. Every other contact column (address, owner, social URLs, hours, service areas, lat/lon…) is overwritten unconditionally by `excluded.*` in `ON CONFLICT DO UPDATE` — a weaker re-run NULLs it (bug.md H-5). No-website leads dedupe on the synthetic `biz://name|city|state|category` key; `get_lead_id_by_url("")` returns None, so engine outputs for them are never persisted (bug.md M-19) and CSV export drops all derived columns because the join key never matches (bug.md H-10).
- Storage modules decode JSON columns into list/dict keys (e.g. `evidence`, `recommended_services`, `service_areas`) but keep the raw `*_json` keys; CSV export merges via `csv_fields_from_row`-style helpers and joins `service_areas_json` with `"; "`.

## Repo conventions

- Commit style: `feat(<area>): ...` (see `git log`: fingerprinting/seo/scoring/opportunities/visual/chat/search/contact/enrichment). Commit message wording has been exact in past features — keep the requested message verbatim.
- Never commit generated/private files: `data/`, `exports/`, `logs/`, `.env`, `business_urls.csv` (all gitignored). Exception: `src/fingerprinting/data/` ships in the repo (`.gitignore` un-hides it) — the fingerprint catalog is code.
- Every file starts with `from __future__ import annotations`.
- All LLM HTTP calls use stdlib `urllib` (`src/llm/openai_responses.py` for extraction, `src/chat/llm.py` for chat) — there is no `openai`/`ollama` pip dependency.
- Tests: stdlib `unittest`, no network, no browser. Shared synthetic fixtures: `tests/scoring_fixtures.py`, `tests/opportunity_fixtures.py`, `tests/search_fixtures.py` (`SearchTestDb`: temp DB + `add_lead`/`add_contact`/`add_seo`/… helpers), `tests/chat_fixtures.py`, `tests/contact_fixtures.py`, `tests/visual_fixtures.py`, `tests/map_fixtures.py`, `tests/enrichment_fixtures.py` (`EnrichmentSqliteFixture`: temp DB + fake page/search fixtures; network replaced via injected fetchers or `unittest.mock.patch`). Tests must be runnable with zero env/API keys; importing `main.py`/`dashboard.py` in tests is safe offline (playwright/streamlit load locally, no browser needed).
- `OPENROUTER_API_KEY` in `.env` for extraction (default model `openrouter/free`, base `https://openrouter.ai/api/v1`); pricing env vars only needed with `--max-cost-usd`.
- Weekly CI exists (`.github/workflows/weekly.yml`) — runs the full pipeline with `business_urls.csv`; not part of the local dev loop.
